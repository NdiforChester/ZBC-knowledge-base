## Team Responsibilities

The team worked as a shared documentation engineering group. Responsibilities included:

- Creating technical notes for assigned topics.
- Using branches for all changes.
- Opening pull requests for review.
- Reviewing and improving each other's work.
- Resolving conflicts and rejected pull requests.
- Organizing documentation into a readable knowledge base.

## Ownership Model

Documentation is shared by the team, but each section should have clear maintainers:

- Linux: Linux contributors and Bash scripting contributors.
- AWS: AWS contributors and cloud reviewers.
- DevOps: Git/GitHub, Docker, Kubernetes, CI/CD, and troubleshooting contributors.
- Repository workflow: Team lead, assistant team lead, GitOps engineers, and QA reviewers.

## Collaboration Expectations

- Communicate before editing another contributor's section heavily.
- Use issues to claim work.
- Keep pull requests focused.
- Give respectful review feedback.
- Fix requested changes in the same PR branch.
- Keep the documentation useful for beginners.
